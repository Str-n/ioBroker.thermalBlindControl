## Preserved values

- All 15 window IDs and names, command and actual-position state IDs, compass orientations, enabled flags and morning-opening preferences.
- `eg_garten` and `dg_gustav` remain disabled.
- Kitchen, K1, K2, parents-room and attic windows retain their morning opt-out.
- Shared actual/command state IDs remain shared. Device endpoints, thermal diagnostics, plans and simulator positions all use **100 = open, 0 = closed**, matching the source blindcontrol adapter's convention.

All exported contact IDs and sun-position filters are empty, all temperature/heat-protection offsets are zero, and all morning targets are fully open. These source fields therefore add no additional active behavior to migrate.

## Initial settings

- `minimumSolarPowerPerWindowW: 20`: minimum daylight allowance for each window, limited by available sunlight.
- `minMovementIntervalMinutes: 60`: at most one automatic move per blind per hour, with each thermal position planned for that full interval.
- `latitude: 50.47`, `longitude: 7.47`, `timezone: Europe/Berlin`: the location specified in the thermal-control plan; the source window export has no location settings.
- Master enable is initially false, dry run is true, and thermal mode is `shadow`.

These booleans initialize newly created runtime states. Existing persistent `global.*` and `windows.<id>.*` switches take precedence when importing into an already configured instance; see the [adapter commissioning instructions](../README.md#commissioning).
